# Spunto IDE (spunto-ide)

An in-browser VS Code (code-server) wearing the Spunto brand — and nothing else. The IDE half of
[`spunto-pack`](../spunto-pack), for a platform that installs it apart from the terminal plumbing:
`spunto-pack` with `installCodeServer: false`, then this.

```jsonc
"features": {
    "ghcr.io/devcontainers/features/common-utils:2": { "username": "vscode" },
    "ghcr.io/coderhammer/features/spunto-pack:1": { "installCodeServer": false },
    "ghcr.io/coderhammer/features/spunto-ide:1": {}
}
```

## Options

| Option | Type | Default | Description |
|---|---|---|---|
| `codeServerVersion` | string | `latest` | code-server version to install, e.g. `4.101.2`. |
| `brand` | `spunto` \| `none` | `spunto` | Rebrand code-server as Spunto (name, icons, the Spunto Light / Dark themes). `none` keeps it as shipped. |
| `strict` | boolean | `false` | Fail the build when code-server cannot be installed. |

No tmux, no dtach, no SSH server, no `/etc/tmux.conf`: those are `spunto-pack`'s, and stay off here
even if an installer exports none of the options (the script's own defaults are code-server only).

## One script, not two

This folder holds only `devcontainer-feature.json` and this README in git. Its `install.sh` and
`brand/` are **spunto-pack's**, copied in by `scripts/sync-shared.sh` before the feature is
published (`.github/workflows/release.yaml`) or tested, and ignored by git. A published feature is
the tarball of its own folder, so it cannot reach `../spunto-pack` once installed — a copy at
packaging time is what keeps one script to fix and one set of icons. What code-server does, how it
is installed and branded: see [spunto-pack's README](../spunto-pack/README.md).

## Tests

```bash
./scripts/sync-shared.sh
npx @devcontainers/cli features test --project-folder . --features spunto-ide
```

| Case | Base | What it pins down |
|---|---|---|
| *(autogenerated)* `test.sh` | devcontainers base | code-server runs, named Spunto, themes built in, licence notices kept; no dtach, no pack tmux.conf. |
| `ide_bookworm` | `debian:bookworm-slim` | On a bare base, `strict: true`: code-server (curl first) and the brand, nothing in a home directory, and tmux, dtach and sshd left out. |
| `brand_none` | `debian:bookworm-slim` | `brand: none`: code-server as shipped. |
